# MAN.3 プロジェクト管理

## 目的とスコープ
（このアプリを）A-SPICE テーラリング版プロセスで段階開発する。

## 開発ライフサイクル
機能（またはフェーズ）を1イテレーションとし、各イテレーション内で
「要求→アーキ→設計→実装→検証→トレース更新」のミニV字を回す。

| フェーズ | 内容 | 状態 | 主要成果物 |
|----------|------|------|-----------|
| フェーズ1 | （最初の機能） | 予定 | SWR-XXX-*, /test |
| フェーズ2 | | 予定 | |

## 体制・役割
- 一人開発。役割は場面で切替：要求分析／設計／実装／レビュー／テスト。
- レビューは PR セルフレビュー＋（必要時）AI ペアレビューで代替（SUP.1 テーラリング）。

## 進捗の可視化
- GitHub Issue（CR）＝作業単位、PR＝完了単位。
- トレーサビリティ・マトリクスの状態で機能の到達度を把握。

## 完了の定義（Definition of Done, 1機能あたり）
1. SWR に要求IDがある 2. 設計(SWD)がある 3. 実装済み
4. テスト(QTC/UTC)が Pass 5. マトリクス更新済み 6. レビュー済みで merge
